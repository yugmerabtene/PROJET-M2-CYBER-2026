# Skill GitHub Project Scrum

## What I Do

Garder GitHub Project, issues et fichiers Scrum locaux alignes avec la gestion de projet.

## When To Use

- Creation user story ou technical task.
- Changement statut Project.
- Verification Sprint 1 a 5.
- Preparation sprint review.
- Synchronisation fichiers EPIC avec issues.

## Source Of Truth

- `documents/07_gestion_de_projet/rendu_principal.md`
- `documents/07_gestion_de_projet/tasks/`
- `documents/07_gestion_de_projet/.github-project-management/PROJECT_SETUP.md`
- `documents/07_gestion_de_projet/.github-project-management/ISSUE_TEMPLATE/*.yml`

## Project Board

- Board : `DevinciWatch Scrum Board`
- Colonnes : `Backlog`, `Sprint Ready`, `In Progress`, `In Review`, `Done`
- Champs : `Epic`, `Story Points`, `Sprint`, `Owner`

## Workflow

1. Identifier item et parent.
2. Verifier DoR pour `Sprint Ready`.
3. Verifier developpement/test/doc/securite pour `In Review`.
4. Verifier DoD complete pour `Done`.
5. Proposer commandes `gh` si auth disponible.
6. Mettre a jour le fichier EPIC local avec `Issue #`.

## Conventions

- `[US-XX.X] Titre`
- `[TASK] Titre`
- `[BUG] Titre`
- Labels : `epic`, `user-story`, `task`, `bug`, `backend`, `frontend`, `qa`, `devops`, `security`, `docs`.

## Git/GitHub Hygiene

Ne jamais mentionner d'IA, d'assistant, d'agent automatise ou d'outil generatif comme auteur, co-auteur, source ou origine. Ne jamais utiliser `Generated by`, `Co-authored-by` lie a une IA, ni de formulation indiquant qu'un contenu a ete produit, nettoye ou corrige par une IA.

## Output Format

Etat local, action GitHub proposee, champs Project, commandes, fichier EPIC a mettre a jour, blockers.
