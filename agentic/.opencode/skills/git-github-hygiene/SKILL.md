# Skill Git GitHub Hygiene

## What I Do

Encadrer les operations Git/GitHub pour qu'elles restent propres, professionnelles, non destructrices et compatibles avec les regles DevinciWatch.

## When To Use

- Preparation commit.
- Preparation issue ou PR.
- Synchronisation GitHub Project.
- Redaction changelog ou release note.
- Verification avant action distante.

## Rules

- Ne jamais faire `git push` sans demande explicite.
- Ne jamais utiliser commande destructive sans validation explicite.
- Ne jamais lire un token depuis un fichier.
- Ne jamais commiter `.env`, token, credentials ou secret.
- Ne jamais mentionner d'IA, d'assistant, d'agent automatise ou d'outil generatif comme auteur, co-auteur, source ou origine.
- Ne jamais utiliser `Generated by`, `Co-authored-by` lie a une IA.
- Ne jamais dire qu'un contenu a ete produit, nettoye ou corrige par une IA.

## Naming Conventions

- Commit : `feat(scope): short description`, `fix(scope): short description`, `chore(scope): short description`, `docs(scope): short description`, `test(scope): short description`.
- User story issue : `[US-XX.X] Titre fonctionnel`.
- Task issue : `[TASK] Titre technique`.
- Bug issue : `[BUG] Titre du probleme`.

## Checklist Before Commit

- `git status` verifie.
- Diff compris.
- Pas de secret.
- Message factuel.
- Tests/documentation mentionnes si pertinents.
- Aucun auteur ou co-auteur non souhaite ajoute.

## Output Format

Action proposee, fichiers concernes, risques, message/titre propose, commandes si necessaire, confirmation requise.
